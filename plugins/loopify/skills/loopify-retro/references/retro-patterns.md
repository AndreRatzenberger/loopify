# Retro Patterns

Look for reusable learning.

## Spec Lessons

- ambiguous language
- hidden subjective requirements
- missing non-goals
- authority surprises

## Check Lessons

- checks that caught real failures
- checks that were too weak
- missing fallback or integration checks
- visual/manual gates discovered late

## Execution Lessons

- repeated failure clusters
- useful diagnostics
- rejected attempts worth preserving
- budget or stop-rule problems

## Template Updates

Recommend exact template changes. Avoid generic "write better specs" advice.
